### 2.1 核心功能一：LLM 动态主题发现

**实现位置**：`pipeline/analyzer.py`

**设计要点**：
- 不预设固定分类，让 LLM 从评论中动态归纳 5-10 个主题
- 每批 30 条评论批量调用，降低 API 成本
- 输出严格 JSON，包含 topic、description、review_ids、sample_count、confidence、conflicting_evidence
- 跨批次合并同名主题，置信度降级规则

**System Prompt（核心约束）**：
```python
SYSTEM_PROMPT = """你是一位资深的产品评论分析师，擅长从 App Store 用户评论中
发现真实的产品问题与诉求。

【输出要求】
1. 必须返回严格的 JSON，不要附加任何解释性文字。
2. 主题必须是动态发现的（5-10 个），不可使用固定类别。
   主题命名应来自评论中实际出现的具体问题（例如"订阅定价过高"，
   而非笼统的"价格"）。
3. 每个主题必须包含以下字段：
   - topic: 主题名称（简短）
   - description: 问题描述（基于评论原文概括）
   - sentiment: positive | negative | neutral
   - review_ids: 支撑该主题的评论 ID 列表
   - sample_count: review_ids 的数量
   - confidence: high | medium | low（证据置信度）
   - conflicting_evidence: 是否存在矛盾反馈（如有则列出，无则空数组）

【防幻觉要求】
1. 你只能基于"用户实际提供的评论数据"作答。
2. review_ids 必须严格来自输入的评论 ID，禁止编造任何 ID。
3. 任何无法从评论中得到充分证据的判断，confidence 必须标为 low。
4. 若证据不足以支撑某结论，宁可少给主题，也不要凑数。
"""
```

**批量处理与动态归纳**：
```python
_BATCH_SIZE = 30

def analyze(reviews, analysis_goal, *, llm_client=None, progress_callback=None):
    # 全部评论 ID 集合，用于事后校验 LLM 是否编造了 ID
    valid_ids = {str(r.get("review_id")) for r in reviews}

    batches = [reviews[i:i+_BATCH_SIZE] for i in range(0, len(reviews), _BATCH_SIZE)]
    merged_topics = {}

    for idx, batch in enumerate(batches, start=1):
        messages = LLMClient.build_messages(
            SYSTEM_PROMPT,
            build_user_prompt(batch, analysis_goal),
        )
        data = llm_client.chat_json(
            messages,
            temperature=settings.llm_temperature,  # 0.3，低温度减少随机性
            max_tokens=settings.llm_max_tokens,
        )

        # 解析主题
        for t in data.get("topics", []):
            name = str(t.get("topic", "")).strip()
            if not name:
                continue
            # 过滤编造的 review_id（防幻觉核心代码）
            rids = [str(x) for x in (t.get("review_ids") or [])
                    if str(x) in valid_ids]
            topic = Topic(
                topic=name,
                description=str(t.get("description", "")).strip(),
                sentiment=str(t.get("sentiment", "neutral")).strip().lower(),
                review_ids=rids,
                sample_count=len(rids),  # 代码重算，不信任 LLM 输出的 sample_count
                confidence=str(t.get("confidence", "low")).strip().lower(),
                conflicting_evidence=[str(x) for x in (t.get("conflicting_evidence") or [])],
            )
            # 跨批次合并同名主题
            if name in merged_topics:
                existing = merged_topics[name]
                existing.review_ids.extend(rid for rid in rids if rid not in existing.review_ids)
                existing.sample_count = len(existing.review_ids)
                # 置信度降级规则：任一批为 low 则整体降为 low
                if topic.confidence == "low" or existing.confidence == "low":
                    existing.confidence = "low"
            else:
                merged_topics[name] = topic

    # 按样本数降序排列
    topics = sorted(merged_topics.values(), key=lambda t: t.sample_count, reverse=True)
    return AnalysisReport(topics=topics, ...)
```

```python
def validate(prd, test_suite, reviews, analysis=None):
    report = ValidationReport()
    valid_review_ids = {str(r.get("review_id")) for r in reviews}

    # ---- 校验 PRD 需求 ----
    for r in prd.get("requirements", []):
        report.total += 1
        req_id = str(r.get("req_id", ""))
        rids = [str(x) for x in (r.get("source_review_ids") or [])]
        valid_rids = [x for x in rids if x in valid_review_ids]

        if not rids:
            # 无任何评论关联 → 标记为假设
            report.failed += 1
            report.assumed_conclusions.append(req_id)
            report.items.append(CheckItem(
                target=req_id, target_type="requirement", passed=False,
                reason="需求未关联任何评论证据，标记为假设，建议移除或补充证据。"
            ))
            continue

        if not valid_rids:
            # 所有 ID 都无效 → 疑似 LLM 编造 → 标记为假设
            report.failed += 1
            report.assumed_conclusions.append(req_id)
            report.items.append(CheckItem(
                target=req_id, target_type="requirement", passed=False,
                reason="需求关联的 review_id 在数据中不存在（疑似 LLM 编造），标记为假设。",
                related_ids=rids
            ))
            continue

        if len(valid_rids) < len(rids):
            # 部分 ID 无效 → 通过但记录明细
            report.passed += 1
            report.items.append(CheckItem(
                target=req_id, target_type="requirement", passed=True,
                reason=f"部分 review_id 无效（{len(rids)-len(valid_rids)} 个被过滤），但仍保留 {len(valid_rids)} 条有效证据。",
                related_ids=valid_rids
            ))
            continue

        report.passed += 1
        report.items.append(CheckItem(
            target=req_id, target_type="requirement", passed=True,
            reason=f"需求有 {len(valid_rids)} 条评论证据支撑。"
        ))

    # ---- 校验测试用例（类似逻辑，校验 req_id 有效性 + review_ids 存在性）----
    for c in test_suite.get("test_cases", []):
        ...
```

### 2.3 核心功能三：LLM 客户端与重试机制

**实现位置**：`models/llm_client.py`

```python
class LLMClient:
    def __init__(self):
        # 初始化时即校验 API Key，缺失直接报错而非运行期崩溃
        missing = settings.validate_llm()
        if missing:
            raise LLMCallError(f"LLM 配置不完整，缺少: {', '.join(missing)}")

        self._client = _OpenAI_CLS(
            api_key=settings.llm_api_key,
            base_url=settings.llm_base_url,  # 兼容 DeepSeek/OpenAI
            timeout=settings.llm_timeout,
        )

    def chat(self, messages, *, temperature=None, max_tokens=None, response_format=None):
        last_err = None
        # 指数退避重试：1s, 2s, 4s
        for attempt in range(settings.llm_max_retries):
            try:
                resp = self._client.chat.completions.create(
                    model=settings.llm_model,
                    messages=messages,
                    temperature=temperature or settings.llm_temperature,
                    max_tokens=max_tokens or settings.llm_max_tokens,
                    response_format=response_format,
                )
                content = resp.choices[0].message.content
                self.total_usage.add(resp.usage)
                return LLMResponse(content=content, usage=self.total_usage, raw=resp)
            except Exception as err:
                last_err = err
                if attempt < settings.llm_max_retries - 1:
                    wait_time = 2 ** attempt  # 1s, 2s, 4s
                    time.sleep(wait_time)
                    continue
                raise LLMCallError(f"LLM 调用失败（重试{settings.llm_max_retries}次）: {last_err}")

    def chat_json(self, messages, *, temperature=None, max_tokens=None):
        """调用并自动解析 JSON 输出"""
        resp = self.chat(messages, temperature=temperature, max_tokens=max_tokens)
        return safe_json_loads(resp.content)  # 容错 JSON 解析
```

```python
def build_rss_url(app_id, country, page):
    """构造 Apple Customer Reviews RSS Feed URL"""
    return (f"https://itunes.apple.com/{country}/rss/customerreviews/"
            f"page={page}/id={app_id}/sortby=mostrecent/json")

def collect_from_url(url, max_pages=10, *, progress_callback=None):
    app_id, country = parse_app_store_url(url)
    country = "us"  # 强制美国区，笔试要求

    # 获取 App 元信息
    meta = _fetch_app_meta(app_id, country)

    reviews = []
    report = CollectReport(app=meta, data_source="rss")

    for page in range(1, max_pages + 1):
        report.pages_attempted += 1
        rss_url = build_rss_url(app_id, country, page)
        try:
            resp = requests.get(rss_url, timeout=settings.http_timeout)
            resp.raise_for_status()
            data = resp.json()
            entries = data.get("feed", {}).get("entry", [])
            if not entries:
                break  # 无更多数据，提前结束
            for entry in entries:
                normalized = _normalize_raw_review(entry, country)
                if normalized:
                    reviews.append(normalized)
            report.pages_succeeded += 1
            report.per_page_counts.append(len(entries))
        except Exception as err:
            report.pages_failed += 1
            report.notes.append(f"第{page}页抓取失败: {err}")

        time.sleep(settings.request_interval)  # 限流：每页间隔1.5s

    report.raw_count = len(reviews)
    return reviews, report
```

## 四、功能实现优先级排序

| 优先级 | 功能 | 实现顺序 | 排序理由 |
|:---|:---|:---|:---|
| **P0** | Apple RSS 评论抓取 | 第1个实现 | 数据源头，所有后续功能依赖 |
| **P0** | 评论清洗去重 | 第2个实现 | 数据质量保障，分析准确性前提 |
| **P0** | LLM 动态主题发现 | 第3个实现 | 核心语义模块，笔试硬性要求，项目差异化核心 |

## 五、实现过程矛盾点与权衡分析

### 矛盾点 1：批量处理大小 vs 响应实时性

| 维度 | 大批量（50条/批） | 小批量（10条/批） |
|:---|:---|:---|
| 优点 | API 调用次数少，成本低，LLM 上下文利用充分 | 单批响应快，用户等待时间短，失败重试代价小 |
| 缺点 | 单批响应慢（30s+），用户等待久，一批失败丢失多 | API 调用次数多，成本高，总耗时长 |

**权衡决策**：**选择 30条/批 的中间值**——
- 30条/批平衡了响应时间（约15-20s/批）和调用次数（500条约17批）
- 每批失败只影响30条，可单独重试，不影响其他批次
- UI 实时展示"第X批/共Y批"进度，缓解用户等待焦虑
- 总耗时控制在 3-5 分钟内，可接受

### 矛盾点 2：LLM 温度高低 vs 结果稳定性

| 维度 | 高温度（0.7+） | 低温度（0.1-0.3） |
|:---|:---|:---|
| 优点 | 输出多样性好，主题发现更有创意，可能发现意外问题 | 结果稳定可复现，同一批评论多次运行结果一致，减少随机性 |
| 缺点 | 结果随机，不可复现，可能输出不一致的主题和 ID | 输出可能刻板，主题发现不够发散，可能遗漏边缘问题 |

**权衡决策**：**选择低温度 0.3，用批量多样性弥补**——
- 笔试项目强调"证据可追溯"和"结果可复现"，低温度更合适
- 0.3 既保证一定的多样性，又控制了随机性
- 通过多批次处理（每批30条，不同批次评论组合不同），自然产生多样性，不需要靠高温度
- 同一输入多次运行结果基本一致，便于调试和验证

### 矛盾点 3：代码注释详细度 vs 代码简洁性

| 维度 | 详细注释 | 简洁代码 |
|:---|:---|:---|
| 优点 | 面试官易理解，体现设计思路，便于维护 | 代码干净，阅读流畅，不冗余 |
| 缺点 | 注释多可能显得啰嗦，部分注释与代码重复 | 复杂逻辑（如防幻觉过滤、置信度降级）缺少说明，面试官可能看不懂设计意图 |

**权衡决策**：**模块头部详细说明 + 关键逻辑行内注释**——
- 每个 Python 文件头部用多行注释说明模块职责、设计要点、依赖关系（如 analyzer.py 头部说明"动态主题发现，不预设分类，防幻觉三重防护"）
- 关键逻辑（ID 过滤、置信度降级、指数退避重试）加行内注释说明为什么这么做
- 简单逻辑（变量赋值、常规循环）不加注释，保持代码简洁
- docstring 说明函数输入输出和异常，不重复实现细节
