## 一、核心数据结构定义

### 1.1 Review（评论）

```python
@dataclass
class Review:
    review_id: str          # 评论唯一标识，来自 Apple RSS entry.id.label
    content: str            # 评论正文
    rating: int             # 用户评分 1-5
    version: str            # App 版本号，如 "2.3.1"
    author: str             # 作者名称
    date: str               # 更新日期，ISO 格式 "2024-01-15T10:30:00Z"
    title: str = ""         # 评论标题（可选）
    language: str = ""      # 语言检测结果，如 "en", "zh"
    cleaning_notes: str = "" # 清洗处理记录，如 "duplicate_removed"
```

**字段约束**：
- `review_id`：非空字符串，全局唯一，用于可追溯关联
- `rating`：整数，范围 1-5，非法值标记为 None 并记录 cleaning_notes
- `content`：非空字符串，空内容标记为 low_quality 但不删除
- `version`：字符串，统一去除前后空格
- `date`：ISO 8601 格式字符串

**JSON 示例**：
```json
{
  "review_id": "1012345678",
  "content": "Great app but the subscription auto-renews without warning. Had to cancel through App Store settings.",
  "rating": 2,
  "version": "3.2.0",
  "author": "FitnessFan2024",
  "date": "2024-03-15T08:22:00Z",
  "title": "Auto-renewal issue",
  "language": "en",
  "cleaning_notes": ""
}
```

### 1.2 Topic（动态主题）

```python
@dataclass
class Topic:
    topic: str                      # 主题名称，LLM动态归纳，如 "订阅自动续费争议"
    description: str                # 问题描述，基于评论原文概括
    sentiment: str                  # 情感倾向: positive | negative | neutral
    review_ids: list[str]           # 支撑该主题的评论 ID 列表（已过滤无效ID）
    sample_count: int               # review_ids 的数量（代码重新计算，不信任LLM输出）
    confidence: str                 # 证据置信度: high | medium | low
    conflicting_evidence: list[str] # 矛盾反馈描述列表，无则空数组
```

**字段约束**：
- `topic`：非空字符串，不使用预设分类，由 LLM 从评论动态归纳
- `review_ids`：列表，每个 ID 必须存在于原始评论数据中，生成时代码过滤
- `sample_count`：整数，必须等于 `len(review_ids)`，代码强制重算
- `confidence`：枚举值 high/medium/low，任一批次为 low 则整体降级为 low
- `conflicting_evidence`：列表，存在对立观点时必须记录

**JSON 示例**：
```json
{
  "topic": "订阅自动续费缺乏提醒",
  "description": "多位用户反映订阅后未收到续费提醒，取消入口隐蔽，导致意外扣费",
  "sentiment": "negative",
  "review_ids": ["1012345678", "1012345679", "1012345680"],
  "sample_count": 3,
  "confidence": "high",
  "conflicting_evidence": ["部分用户认为价格合理，未提及续费问题"]
}
```

### 1.3 Requirement（PRD 需求）

```python
@dataclass
class Requirement:
    req_id: str                # 需求唯一标识，如 "REQ001"
    title: str                 # 需求标题
    description: str           # 需求描述
    priority: str              # 优先级: P0 | P1 | P2 | P3
    source_topic: str          # 来源主题名称
    source_review_ids: list[str] # 来源评论 ID 列表
    acceptance_criteria: str   # 验收标准
    confidence: str            # 置信度: high | medium | low
```

**字段约束**：
- `req_id`：非空字符串，格式 "REQ" + 三位数字
- `priority`：枚举值 P0-P3，P0 最高
- `source_review_ids`：列表，每个 ID 必须存在于原始评论数据
- `acceptance_criteria`：非空字符串，描述可验证的验收条件

**JSON 示例**：
```json
{
  "req_id": "REQ001",
  "title": "续费前3天推送提醒",
  "description": "在订阅自动续费前3天，通过推送和站内消息提醒用户，提供取消入口",
  "priority": "P0",
  "source_topic": "订阅自动续费缺乏提醒",
  "source_review_ids": ["1012345678", "1012345679"],
  "acceptance_criteria": "用户在续费前3天收到推送通知，消息中包含明确的取消订阅入口",
  "confidence": "high"
}
```

### 1.4 VersionPlan（版本规划）

```python
@dataclass
class VersionPlan:
```

### 1.5 TestCase（测试用例）

```python
@dataclass
class TestCase:
    case_id: str             # 用例唯一标识，如 "TC001"
    req_id: str              # 关联需求 ID
    title: str               # 用例标题
    preconditions: str       # 前置条件
    steps: list[str]         # 测试步骤列表
    expected_result: str     # 预期结果
    source_review_ids: list[str] # 来源评论 ID 列表
    type: str                # 用例类型: functional | regression | edge_case
    confidence: str          # 置信度: high | medium | low
```

**字段约束**：
- `case_id`：非空字符串，格式 "TC" + 三位数字
- `req_id`：必须存在于 PRD 需求列表中，生成时过滤无效 ID
- `source_review_ids`：列表，每个 ID 必须存在于原始评论数据
- `steps`：非空列表，至少1步
- `expected_result`：非空字符串，可验证

**JSON 示例**：
```json
{
  "case_id": "TC001",
  "req_id": "REQ001",
  "title": "续费前提醒推送验证",
  "preconditions": "用户已订阅，距离续费日3天",
  "steps": ["登录已订阅账号", "等待系统到达续费前3天时间点", "检查推送通知和站内消息"],
  "expected_result": "用户收到续费提醒，消息中包含明确的取消订阅入口",
  "source_review_ids": ["1012345678", "1012345679"],
  "type": "functional",
  "confidence": "high"
}
```

### 1.6 ValidationReport（验证报告）

```python
@dataclass
class ValidationReport:
    total: int                        # 总验证项数
    passed: int                       # 通过项数
    failed: int                       # 未通过项数
    pass_rate: float                  # 通过率百分比
    items: list[CheckItem]            # 验证项明细列表
    assumed_conclusions: list[str]    # 无证据支撑的结论 ID 列表
    notes: list[str]                  # 备注信息
```

```python
@dataclass
class CheckItem:
    target: str           # 验证对象 ID（需求 ID 或用例 ID）
    target_type: str      # 对象类型: requirement | test_case
    passed: bool          # 是否通过
    reason: str           # 原因说明
    related_ids: list[str] # 关联的有效评论 ID 列表
```

**JSON 示例**：
```json
{
  "total": 15,
  "passed": 15,
  "failed": 0,
  "pass_rate": 100.0,
  "items": [
    {
      "target": "REQ001",
      "target_type": "requirement",
      "passed": true,
      "reason": "需求有 2 条评论证据支撑",
      "related_ids": ["1012345678", "1012345679"]
    }
  ],
  "assumed_conclusions": [],
  "notes": ["共验证 15 项，通过 15 项，通过率 100.0%"]
}
```

### 1.7 PipelineResult（流水线聚合结果）

```python
@dataclass
```

### 2.2 Cleaner（清洗模块）

```python
def clean(
    reviews: list[dict],
    *,

    清洗评论数据：去重、字段标准化、语言检测、垃圾过滤。
```

### 2.3 Analyzer（AI 动态分析模块）

```python
def analyze(
    reviews: list[dict],
    analysis_goal: str,
    *,
    llm_client: LLMClient | None = None,
    progress_callback: Callable[[str, dict], None] | None = None
) -> AnalysisReport:
    """
    AI 动态主题发现。
    - 每批30条评论调用 LLM
```

## 四、异常口径与错误处理

| 异常类型 | 触发条件 | 处理方式 | 用户提示 |
|:---|:---|:---|:---|
| `CollectorError` | App 链接解析失败 / RSS 请求失败 / 网络错误 | 记录错误，步骤标记 failed，不影响已完成步骤 | "评论抓取失败：{原因}，请检查链接或网络" |
| `LLMCallError` | API Key 缺失 / 调用超时 / 限流 / 解析失败 | 指数退避重试3次，耗尽后抛出，步骤标记 failed | "AI 分析失败：{原因}，请检查 API Key 配置或稍后重试" |
| `ValueError` | 评论列表为空 / 输入参数无效 | 直接抛出，步骤标记 failed | "输入数据为空，请先抓取或导入评论" |
| JSON 解析失败 | LLM 输出非严格 JSON | safe_json_loads 容错解析，仍失败则记录日志并重试 | （内部处理，用户无感知） |
| 无效 review_id | LLM 编造的 ID 不在原始数据中 | 生成时过滤，validator 再校验，全部无效的标记 assumption | 验证报告中显示 "N 个无证据结论已标记为假设" |
| 配置缺失 | .env 中无 API Key | LLMClient 初始化时校验，缺失则抛异常；UI 自动加载离线缓存 | "LLM 配置缺失，已加载离线缓存示例数据" |

## 五、配置参数定义

| 参数 | 环境变量 | 默认值 | 说明 |
|:---|:---|:---|:---|
| LLM API Key | `LLM_API_KEY` / `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` | （必填） | 大模型 API 密钥 |

| Max Review Pages | `MAX_REVIEW_PAGES` | `10` | 最大抓取页数 |
| Request Interval | `REQUEST_INTERVAL` | `1.5` | 每页请求间隔（秒） |
| HTTP Timeout | `HTTP_TIMEOUT` | `15` | HTTP 请求超时（秒） |
| Default Country | `DEFAULT_COUNTRY` | `us` | 默认 App Store 国家区 |
